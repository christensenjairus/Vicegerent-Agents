# Managed Homebrew packages

`packages.json` is the desired state for host tools whose CLI behavior is part of the platform. Repository-managed entries name immutable, version-qualified formulae under the root `Formula/` directory. Replacement cleanup falls back to an installed formula's short name when its old tap formula has already been deleted, so orphaned kegs are still unpinned and removed. The repository is tapped from the public GitHub clone as `vicegerent/packages`, so host package reconciliation does not require GitLab credentials; before applying, the managed tap checkout is synchronized to the exact commit of the invoking Vicegerent checkout, including a pre-merge task branch.

```bash
./vicegerent host-packages check
./vicegerent host-packages apply
```

`check` is read-only and fails when, among other things, the Homebrew prefix cannot be resolved, a required formula is absent, the binary is not on PATH, the linked binary belongs to another formula, the version probe does not report the declared version, the formula is not pinned, or a declared replacement is still installed. It also verifies the repository-owned native notification helper's source digest, version, stable designated identity, signature, macOS notification authorization, and **Persistent** Alert Style. `apply` reconciles the exact Homebrew formulae, compiles and signs the helper application under `~/.vicegerent/notifier`, registers it with LaunchServices, requests notification authorization, and removes obsolete `terminal-notifier` formulae. The confirmation lists those removals; `--yes` accepts them non-interactively.

Every `vicegerent start` and `vicegerent mcp start` runs `check` and automatically runs `apply --yes` before MCP startup when anything is drifted. Independent formula, notifier, and obsolete-formula probes run concurrently so the clean path is bounded by the slowest probe rather than their cumulative runtime; all Homebrew mutations remain serialized.

A repository-formula upgrade is a repository change: Renovate updates the desired version in `packages.json`, then the merge-request pipeline runs `host/brew/generate.py`, downloads the declared immutable release artifacts, calculates their SHA-256 checksums, renders a new versioned formula from `host/brew/templates/`, updates the manifest's formula reference, and commits those generated files back to the Renovate branch. Old versioned formulae are never edited or deleted, which preserves rollback. A non-recursive follow-up pipeline validates the generated branch head. Homebrew still owns transitive dependencies, so this contract pins direct host tools rather than claiming a byte-for-byte dependency closure.

Each manifest entry declares its upstream release source and generator strategy. New releases appear in Renovate's dependency dashboard and require explicit approval before Renovate opens an MR. CI owns repository formula and checksum generation; the remaining human gate is installing the package on a supported Mac and verifying `./vicegerent host-packages check` and `./vicegerent mcp doctor` before merge. If upstream packaging or build instructions for a repository formula change, update the corresponding checked-in template in the same MR rather than editing generated formulae.
